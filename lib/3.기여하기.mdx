# 기여하기

BDS(Buzzle Design System)는 오픈소스 프로젝트로, 모든 형태의 기여를 환영해요.   
이 페이지에서는 BDS 프로젝트에 기여하는 방법에 대해 설명해요.

## 기여 방법

BDS에 기여하는 방법은 다양해요.

1. **코드 기여**: 버그 수정, 새 기능 추가, 성능 개선 등
2. **문서 개선**: 설명, 예제, 용례 추가 및 개선
3. **디자인 기여**: 컴포넌트 디자인 개선, 새 디자인 제안
4. **테스트 추가**: 단위 테스트, 통합 테스트, 시각적 테스트 작성
5. **사용 사례 공유**: 실제 사용 사례와 피드백 공유
6. **이슈 리포트**: 버그 보고 및 개선 제안

## 개발 환경 설정

### 요구사항

- Node.js 22.14.0 이상
- Yarn 4.8.1 이상

### 로컬 개발 환경 설정

1. 저장소 복제:

```bash
git clone https://github.com/teamBuzzle/bds.git
cd bds
```

2. 의존성 설치:

```bash
yarn install
```

3. 개발 서버 실행:

```bash
yarn dev
```
또는 단축키로 프로젝트를 실행할 수 있어요 (추천)   
MAC, Linux : <kbd>⌘</kbd> + <kdb>Shift</kdb> + <kbd>B</kbd>   
Windows : <kbd>Ctrl</kbd> + <kdb>Shift</kdb> + <kbd>B</kbd>

이제 http://localhost:3000 에서 Storybook을 통해 BDS 컴포넌트를 확인할 수 있습니다.

## 코드 기여 가이드라인

### 브랜치 전략

- `main`: 프로덕션 브랜치 (기본)
- `feat/*`: 새 기능 개발 브랜치
- `fix/*`: 버그 수정 브랜치
- `docs/*`: 문서 관련 변경 브랜치
- `style/*`: 코드 스타일 변경 브랜치
- `refactor/*`: 리팩토링 브랜치
- `perf/*`: 성능 개선 브랜치
- `test/*`: 테스트 관련 브랜치
- `build/*`: 빌드 시스템 변경 브랜치
- `ci/*`: CI 설정 변경 브랜치
- `chore/*`: 기타 변경사항 브랜치
- `hotfix/*`: 긴급 버그 수정 브랜치

### 코드 스타일

BDS는 ESLint와 Prettier를 사용하여 코드 스타일을 관리합니다. 코드를 제출하기 전에 다음 명령을 실행해 주세요:

```bash
yarn lint
yarn prettier
```

### 커밋 메시지 규칙

BDS는 [Conventional Commits](https://www.conventionalcommits.org/) 규칙을 따릅니다:

```
<type>[optional scope]: <description>

[optional body]

[optional footer]
```

**Type**:
- `feat`: 새 기능
- `fix`: 버그 수정
- `docs`: 문서 변경
- `style`: 코드 스타일 변경 (포맷팅, 세미콜론 추가 등)
- `refactor`: 기능 변경 없는 코드 리팩토링
- `perf`: 성능 개선
- `test`: 테스트 추가 또는 수정
- `build`: 빌드 시스템 또는 외부 의존성 변경
- `ci`: CI 설정 파일 및 스크립트 변경
- `chore`: 기타 변경사항

예시:
```
feat(button): 그라데이션 버튼 스타일 추가

버튼 컴포넌트에 그라데이션 스타일 적용 옵션 추가.
상단에서 하단으로 그라데이션 효과를 적용할 수 있습니다.

Closes #123
```

### 풀 리퀘스트(PR) 프로세스

1. 메인 브랜치에서 새 브랜치를 생성합니다:
   ```bash
   git checkout -b feature/my-feature main
   ```

2. 변경사항을 구현하고 테스트를 추가합니다.

3. 변경사항을 커밋합니다:
   ```bash
   git commit -m "feat: 새 기능 추가"
   ```

4. 원격 저장소에 푸시합니다:
   ```bash
   git push origin feature/my-feature
   ```

5. GitHub에서 Pull Request를 생성합니다.

6. 코드 리뷰를 받고 필요한 변경사항을 적용합니다.

7. 변경사항이 승인되면 PR이 병합됩니다.

## 컴포넌트 개발 가이드라인

### 새 컴포넌트 추가

1. 컴포넌트 파일 생성:
   ```
   components/
   └── MyComponent/
       ├── index.ts
       ├── MyComponent.tsx
       ├── MyComponent.stories.tsx
       └── MyComponent.test.tsx
   ```

2. 컴포넌트 구현(React 19 이상 사용):
   ```tsx
   // MyComponent.tsx
   import type { PropsWithChildren } from 'react';
   import { styled } from '@mui/material/styles';
   
   export interface Props extends PropsWithChildren {
     /** 추가 클래스 */
     className?: string;
     /** 정렬 방향 */
     align?: 'left' | 'center' | 'right';
   }
   
   const StyledComponent = styled('div')(({ theme }) => ({
     // 스타일 구현
   }));
   
   export const MyComponent = ({ children, className, align = 'left', ref, ...otherProps }: Props) => {
       return (
         <StyledComponent 
           ref={ref}
           className={className}
           align={align}
           {...otherProps}
         >
           {children}
         </StyledComponent>
       );
     };
   ```

3. 스토리 생성:
   ```tsx
   // MyComponent.stories.tsx
   import { Meta, StoryObj } from '@storybook/react';
   import { MyComponent } from './MyComponent';
   
   const meta = {
     title: 'Components/MyComponent',
     component: MyComponent,
     parameters: {
       layout: 'centered',
     },
     argTypes: {
       align: {
         control: 'select',
         options: ['left', 'center', 'right'],
         defaultValue: 'left',
       },
     },
   } satisfies Meta<typeof MyComponent>;
   
   export default meta;
   type Story = StoryObj<typeof meta>;
   
   export const Basic: Story = {
     args: {
       children: '기본 컴포넌트',
     },
   };
   
   export const Center: Story = {
     args: {
       children: '가운데 정렬 컴포넌트',
       align: 'center',
     },
   };
   ```

4. 테스트 작성:
   ```tsx
   // MyComponent.test.tsx
   import { render, screen } from '@testing-library/react';
   import { MyComponent } from './MyComponent';
   
   describe('MyComponent', () => {
     it('renders children correctly', () => {
       render(<MyComponent>테스트 내용</MyComponent>);
       expect(screen.getByText('테스트 내용')).toBeInTheDocument();
     });
     
     it('applies align prop correctly', () => {
       const { container } = render(
         <MyComponent align="center">가운데 정렬</MyComponent>
       );
       expect(container.firstChild).toHaveStyle({ textAlign: 'center' });
     });
   });
   ```

5. 인덱스 파일 생성:   
인덱스 파일을 생성할 때는 항상 Named Export를 사용해주세요.
   ```tsx
   // index.ts
   export { MyComponent } from './MyComponent';
   ```

### 컴포넌트 개선

기존 컴포넌트를 개선할 때는 다음 사항을 고려하세요:

1. 기존 API를 존중하고, 하위 호환성을 유지하세요.
2. 필요한 경우에만 새 기능을 추가하세요.
3. 성능에 영향을 미칠 수 있는 변경사항은 성능 테스트와 함께 제출하세요.
4. 항상 기존 테스트를 업데이트하고 필요한 경우 새 테스트를 추가하세요.

## 문서 기여 가이드라인

문서를 개선하거나 추가할 때 다음 가이드라인을 참고하세요:

1. 명확하고 간결한 언어를 사용하세요.
2. 코드 예제는 항상 실행 가능하고 최신 API를 반영해야 합니다.
3. 개념보다 사용 사례와 예제에 중점을 두세요.
4. 문서 변경사항을 설명하는 스크린샷이나 다이어그램을 추가하세요.
